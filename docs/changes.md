## 开始之前：看懂本文档需要的 6 个概念

| 概念 | 一句话解释 |
|---|---|
| **前端 / 后端** | 前端=浏览器里跑的界面（本项目用 React）；后端=服务器上跑的程序（本项目用 Node.js + Express），负责真正干活：调 AI、查数据库 |
| **API / 接口** | 前后端之间"约定好的对话格式"。前端发 HTTP 请求（如 `POST /api/chat`），后端回 JSON 数据 |
| **SSE** | Server-Sent Events，服务器"连续推送"技术。AI 回答是一个字一个字蹦出来的，靠的就是它：后端把回答切成小段不停发给前端 |
| **RAG** | Retrieval-Augmented Generation，检索增强生成。让 AI 回答**之前先去查资料**（本项目=查你上传的文档），再根据查到的内容回答——防止 AI 瞎编 |
| **Docker** | 把程序+依赖打包成"集装箱"（镜像），在任何机器上都能原样运行，不用再装一堆环境 |
| **.env 文件** | 存密码、API Key 等机密的配置文件。已被 git 忽略（.gitignore），**永远不会提交到 GitHub** |

其它术语（JWT、pgvector、nginx……）在出现的地方就地解释。

## 第一阶段：初始版本——7 个里程碑（2026-10-09 ~ 10-10）

一次性提交：`51a095c`（63 个文件）。虽然是"一次提交"，但开发是分 7 步走的，每步都单独验收过：

### 里程碑 1：后端骨架

**做了什么**：用 Express 搭起后端的"地基"——三个接口（health 健康检查 / upload 上传 / chat 对话）、统一的响应格式 `{code, data, message}`、统一的错误处理中间件。

**为什么先做这个**：接口是前后端的地基。先把"约定"定好，后面所有功能都往这个骨架上挂。

**涉及文件**：`server/src/app.ts`、`server/src/routes/`、`server/src/utils/response.ts`

**小白概念**：
- **中间件（middleware）**：Express 里"每个请求都会路过"的处理函数。比如错误中间件统一捕获所有报错，不用每个接口自己写 try/catch。

### 里程碑 2：文档解析入库

**做了什么**：上传 `.pdf/.md/.txt` 文档后，自动解析出纯文本 → 切成 800 字一块（相邻块重叠 100 字）→ 调 Qwen 的向量化接口把每块变成 1024 个数字（向量）→ 存进 PostgreSQL 的 pgvector 插件里。

**为什么**：AI 没法"整篇读"长文档。切块+向量化后，用户提问时就能用"数学上的相似度"找出最相关的几块喂给 AI。

**涉及文件**：`server/src/services/ingestion.ts`、`server/src/services/embedding.ts`、数据库表 `documents` / `chunks`

**小白概念**：
- **向量（embedding）**：把一段文字变成一串数字，意思相近的文字数字也相近。"年假"和"带薪休假"的向量距离，远小于"年假"和"报销"的距离——这就是"语义搜索"的原理。
- **为什么切块要重叠 100 字**：一句话可能正好被切断，重叠让边界处的信息不丢。

### 里程碑 3：检索 + 生成（RAG 核心）

**做了什么**：用户提问 → 问题也向量化 → 在 pgvector 里找出最相似的块（带相似度分数）→ 拼进提示词发给 Qwen → Qwen 的回答通过 SSE 一个字一个字推给前端。回答里的 `[1] [2]` 引用标注可以点击，高亮对应的来源卡片。

**涉及文件**：`server/src/routes/chat.ts`、`server/src/services/agent.ts`、`server/src/services/qwenChat.ts`、前端 `web/src/components/ChatPanel.tsx` / `ChatMessage.tsx`

**小白概念**：
- **流式输出**：模型生成一个词就立刻发给前端一个词，而不是等全文生成完。用户感知就是"打字机效果"，实际等待时间大幅缩短。

### 里程碑 4：工具调用（Agent）

**做了什么**：把"查知识库"从写死逻辑改成 AI 可自主调用的**工具**（function calling）。AI 先看问题，自己决定"要不要查、查什么关键词"。后来又加了第二个工具 `web_search`（联网搜索，当时没配 Key 没启用）。

**为什么**：这是从"固定流程"到"Agent"的跨越——AI 变成会自己拿工具干活的助手，而不是只会背书的模型。

**涉及文件**：`server/src/services/agent.ts`（Agent 循环）、`server/src/services/tools.ts`（工具注册与执行）

**踩坑**：Node 21 下检测"用户是否关闭页面"不能用 `req.on('close')`（请求体一读完就误触发），必须用 `res.on('close')` 配合 `res.writableEnded` 判断——否则 SSE 一开始就被当成"客户端断开"。

### 里程碑 5：登录、权限、审计（RBAC）

**做了什么**：JWT 登录（admin / demo 两个内置账号）、两种角色（管理员能上传删除文档、看审计日志；普通用户只能对话）、所有敏感操作记审计日志。

**小白概念**：
- **JWT**：登录成功后服务器发一张"加密门票"（token），之后每次请求都带着它证明"我是登录过的用户"。前端存在 localStorage，过期后自动踢回登录页。
- **密码存储**：数据库里存的不是密码本身，而是单向哈希（scrypt 加盐）。就算数据库泄露，别人也还原不出原密码。

### 里程碑 6：监控与降级

**做了什么**：pino 结构化日志（每个请求、每次对话的耗时/token 数都记下来）、模型流式空闲超时保护（AI 卡住 30 秒自动掐断并友好提示，而不是让用户无限等）、空知识库兜底（引导先上传文档）。

**为什么**："能跑"和"敢给人用"之间隔着这些——出问题要能看到日志，坏了要有兜底。

### 里程碑 7：自动化评测

**做了什么**：用 promptfoo 跑了 30 道测试题（事实题 / 超范围题 / 对抗题 / 模糊题），30/30 通过，引用率 83%，幻觉风险 0，平均延迟 4.7 秒，总成本 ¥0.06。

**为什么**：改提示词之后怎么知道没改坏？靠评测兜底。`eval/` 目录整套可复跑。

## 第二阶段：部署上线（2026-10-10）

提交：`1a1de96`（部署配置）→ `9c63da6`（部署文档）

**做了什么**：
1. 写了多阶段 Dockerfile：一个镜像里先构建前端+后端，再只把产物拷进干净的运行时镜像（体积小、不含源码和构建工具）
2. docker-compose 编排两个容器：`ai-kb-app`（应用）+ `ai-kb-pg`（数据库，只允许内网访问）
3. 服务器上已有的 pick-radar 网站独占 80 端口，于是在它的 nginx 里加了一个 `/kb/` 路径规则：访问 `http://139.224.67.182/kb/` 就转发给本项目

**小白概念**：
- **反向代理（nginx）**：门口的"总台接待"。一个 IP 只有一个 80 端口，nginx 按路径分流——`/` 给 pick-radar，`/kb/` 给本项目，两个网站共用一台服务器互不干扰。
- **多阶段构建**：像装修——毛坯房（node 镜像）里施工，完工后只把家具（编译产物）搬进新家（干净的运行镜像），施工队材料全留在旧房子里。

**踩坑（这条值得背下来）**：nginx 的 `location /kb/` 里，`set $kb_app ...` 必须写在 `rewrite ... break` **之前**——`break` 会终止其后所有 rewrite 模块指令（包括 set），导致变量没赋值，页面 500。

全程命令留痕在 [deployment.md](deployment.md)（含回滚方案、日常运维命令）。

## 第三阶段：上线后的迭代

### 3.1 切换标签页不丢对话 + "新对话"按钮（2026-10-10，`b8c00c0`）

**问题**：点击"文档管理"再切回"对话"，聊天记录全没了，也无法开启新对话。

**原因**：原代码里切 tab 是"卸载旧组件、挂载新组件"（条件渲染），组件一卸载，它内存里的聊天记录就销毁了。

**修法**：三个 tab 的组件**永远都挂载着**，只是用 HTML 的 `hidden` 属性把不显示的藏起来。切 tab = 换个隐藏方式，组件和它的数据原地不动。顺带红利：切走再切回来，正在打字的 AI 回答不会被打断。

**涉及文件**：`web/src/App.tsx`（always-mount + hidden）、`web/src/components/ChatPanel.tsx`（新增"新对话"按钮：清空记录+中止进行中的流）

### 3.2 回答支持表格、代码块、行内代码（2026-10-10，`3c505c4`）

**问题**：AI 的回答里就算有表格和代码，页面上也只能看到一堆竖线和反引号符号（原始 Markdown 文本）。

**修法**：
- 前端把自写的迷你 Markdown 渲染器升级：认识 GFM 表格（`| 列1 | 列2 |` + `|---|---|` 分隔行）、围栏代码块（```开头结尾）、行内代码（`x`）
- 流式输出的坑：回答是逐字到达的，表格经常"只有一半"。渲染器规定：分隔行没到就先不当表格（避免渲染结果来回跳）；代码块没闭合就按"已收到的部分"渲染
- 后端提示词加一条规则：罗列/对比结构化信息优先用表格输出——**前端能渲染什么，得告诉后端的 AI 让它配合输出什么**

**涉及文件**：`web/src/components/ChatMessage.tsx`、`web/src/index.css`、`server/src/services/agent.ts`

### 3.3 ECharts 图表块（2026-10-12，`ca7ac16`；布局修复 `d63cc01`）

**做了什么**：AI 需要可视化时输出一个 ` ```echarts ` 围栏块，内容是 ECharts 配置（严格 JSON）。前端看到这种围栏，把 JSON 解析后交给 ECharts 画成图（柱状/折线/饼图）。

**关键设计**：
- **按需加载**：echarts 库有 560KB。用 React.lazy 单独打包成独立文件，只有真出现图表时浏览器才下载它——主包体积不变（161KB）
- **流式友好**：JSON 没传完时显示"图表生成中"转圈占位；传完后解析失败则回退显示原始代码（便于排查）
- **防幻觉布局（d63cc01）**：AI 生成的图表配置布局不可控，图例经常压在 x 轴标签上。前端在画图前强制"摆正"：图例固定顶部单行、绘图区高度预留、坐标轴标签不再溢出

**涉及文件**：`web/src/components/EChartBlock.tsx`（新增）、`web/src/components/ChatMessage.tsx`

**小白概念**：
- **按需加载（code splitting）**：把大库拆成单独文件，用到才下载。就像行李箱分装——常用的小包随身带，滑雪板到滑雪场再取。

### 3.4 联网搜索上线（2026-10-12，`3813e40`）

**做了什么**：注册 Tavily（AI 专用搜索服务，免费档每月 1000 次搜索），把 API Key 配到 `.env`，`web_search` 工具即刻启用。此后问"今天黄金金价"这类实时问题，AI 会先联网搜索再基于网页结果回答，来源卡片可点击跳原文。

**踩坑（有趣的一条）**：配好 Key 后第一次测试，AI 竟然说"web_search 工具当前不可用"然后拒答——其实工具好好的。排查发现是提示词里写了"（如可用）"四个字，AI 自己脑补出"可能不可用"。修法：提示词按**真实配置动态生成**——配了 Key 就明确写"必须调用"，没配才写"不可用"。

**教训**：提示词是写给 AI 看的"员工手册"，每个含糊措辞都可能被 AI 过度解读。

**涉及文件**：`server/src/services/agent.ts`（动态提示词）、`server/src/services/webSearch.ts`

### 3.5 页头额度徽标（2026-10-12，`1e13f97`）

**做了什么**：页头右侧显示"联网搜索 1000/1000"徽标——Tavily 官方有 `/usage` 查询接口，后端透传（60 秒缓存，避免每次刷新页面都打外网）。剩余 <10% 变黄、用尽变红、点击徽标立即刷新。

**已知怪象**：Tavily 官方的"已用次数"统计有延迟，实际搜了几次仍显示 0——徽标忠实展示官方数据，等它更新自动对上。

**涉及文件**：`server/src/routes/usage.ts`（新增）、`server/src/services/webSearch.ts`、`web/src/App.tsx`、`web/src/api.ts`
